# Open questions

1. **Account format.** The CSV uses number and name, such as `41100 License Revenue`. Confirm on a test import that NetSuite matches it; child accounts may need the full path.
2. **OEM license.** Does AIStor OEM License use the same accounts and rule as the direct licenses?
3. **Platform training subscription.** Is it recognized like the live trainings or like a subscription?
4. **Classes in production.** License, Support, Training and Professional Services must exist in production before this load.
5. **Not in this load.** The Items tab lists Surcharge Fee for Marketplace and Reseller Margin (presented as a discount) as TBD. No Professional Services SKUs yet; 42100 Professional Services Revenue is ready when there are.
6. **Template header.** The template spells `Revenue Recogition Rule`. Kept as is; it only needs to match when mapping the import.
7. **Long-term deferred revenue.** Items post to 23100 Deferred Revenue - ST. The part earned more than 12 months out is reclassed to 23200 Deferred Revenue - LT by a period-end journal entry. Confirm the Unbilled, Billed and Paid accounts under 23200 are still needed.
8. **Show Display Name with Item Codes.** Setup > Company > General Preferences. Shows code and name together in item fields. If turned on, later CSV imports that reference items need the display name too, or fail with Invalid Parent Reference Key. Decide before the sales order and invoice loads.
9. **License delivery trigger.** License keys are issued manually; the issue date (available in BigQuery operating data) should drive invoicing and the revenue start. Options: (a) Can be fulfilled/received = Yes on license items and a fulfillment posted when the key is issued, with revenue plans created on fulfillment; (b) a custom revenue recognition event, created by script or integration; (c) no fulfillment, with the revenue start date set on the order line from the key issue date. Decide before the load: whether Can be fulfilled/received can change after items are used on transactions is unclear.
10. **Portal sales.** Smaller businesses and individuals buy AIStor through a portal, about monthly, and revenue is recognized immediately. These items defer revenue, so portal sales need either a separate portal item with Direct Revenue Posting = Yes and no deferred revenue account, or no item at all if portal sales reach NetSuite as a summary journal entry from the payment processor.
11. **Revenue recognition rules.** None are set up yet, so both rule columns stay blank. NetSuite may require a rule on items that have a deferred revenue account; the sandbox import will show whether the load fails without one. Either way the items need rules before they are used on transactions, added later with an update import keyed on External ID.
